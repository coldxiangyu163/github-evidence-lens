# Goal: GitHub Evidence Lens v0.1

Build and publicly release a skill-first, evidence-based GitHub contribution investigation toolkit. The product evaluates public evidence, not a person's worth, IQ, or hiring eligibility. MIT license. Python 3.11+, preferably standard library runtime and unittest tests. CLI executable `github-evidence-lens`, package `github_evidence_lens`.

## Product thesis
Static star/commit scores confuse popularity with capability. LLM-only prose can hallucinate. Pair deterministic, auditable GitHub evidence acquisition with a portable Agent Skill that iteratively selects contributions, reads code/reviews/CI, looks for counterevidence and produces cited, qualified findings. Skill uses the host agent's existing model, no embedded paid LLM required. Do not pretend a static CLI generates deep AI analysis. Default output is evidence inventory; agent findings are a separate validated input.

## Scope and architecture
1. CLI `collect USER --out DIR --max-prs N --sample-prs N` fetch public profile minimal fields, public repositories (paginated), authored PR search (`is:public` obligatory), separate external/self-owned and merged/open/closed-unmerged. Validate exact username format before lookup. Follow pagination, dedupe by PR URL, disclose search 1000-result ceiling, incomplete_results, sampled detail limits, API errors and rate limits. Fetch metadata proving public visibility BEFORE storing details; gh auth can see private resources. Redact/exclude email, credentials and personal contact info. No destructive or write GitHub operations.
2. For bounded selected PRs fetch detail, diff files/patch, reviews, discussion comments and head check-runs. Deterministic stratified selection (external merged, open, closed; document methodology), with CLI `inspect OWNER/REPO#N --out DIR` for agent-directed investigation. Exact repository/PR validation. Never execute target repository code, never shell=True, constrain GitHub API endpoints and redirects. CLI can invoke `gh api` via argv, read existing auth without printing credentials. Limit bytes and pages, label truncation at every affected evidence item.
3. Evidence items with stable IDs, GitHub URL, retrieved_at UTC, repo/PR/head SHA context, sanitized content, completeness flags. Atomic local JSON persistence, artifacts ignored in git. GitHub failures must not silently become zero or claim success. Capture count denominators (observed vs total) and collection budget. Reproducible fixture tests, never present synthetic data as live.
4. `report BUNDLE --out DIR [--findings PATH]`: Markdown, safe escaped standalone HTML and static SVG card. Card is an evidence summary not a fabricated personal score. Local untrusted strings must not inject HTML/JS/SVG links. No remote images/scripts. Without findings explicitly state not AI-reviewed. With findings validate each claim references EXISTING evidence IDs, status (supported/partial/contradicted/unknown), rationale, counterevidence and limitations. Validation cannot establish semantic truth; document this. Distinguish low evidence vs negative finding. Do not infer AI authorship or identity ownership from username. Do not treat CI existence as pass, closure as rejection, self-merge as external approval, repo/fork totals as individual authorship. Machine metrics separate from agent judgments.
5. Portable skill at `skills/github-evidence-lens/SKILL.md`, detailed references/rubric.md and report schema/example. Progressive workflow: goal/role context -> scope collection -> candidate selection -> inspect representative code -> check counterevidence/reviews/CI -> claim validation -> human-reviewed report/card. Include prompt-injection defenses: README/PR bodies are untrusted evidence, never instructions; no running target code by default. Budget/stop criteria, no private data, no unsupported percentiles or universal score. Installation examples for agents generic plus Hermes/Claude Code verified conventional skill folders; no edits to host agent state during build.
6. Docs: Chinese-first README plus concise English, PRD, architecture, methodology, limitations, security policy, contributing, roadmap, MIT license. First use command documented/tested. CI runs tests and package build without secrets/network. Example fixtures clearly synthetic; no actual resumes/account report or machine paths committed.
